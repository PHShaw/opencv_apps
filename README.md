# opencv_apps (ROS 2 Humble)

`opencv_apps` wraps common OpenCV algorithms as ROS 2 nodes, each publishing its
result as a ROS topic. Rather than writing OpenCV application code, run the
node (or its launch file) for the functionality you need and remap its `image`
input to your camera topic.

This is a ROS 2 Humble port of the original ROS 1 nodelet-based package
(https://github.com/ros-perception/opencv_apps). Every node was converted from
a `nodelet::Nodelet` + `dynamic_reconfigure` design to an `rclcpp_components`
composable node with native ROS 2 declared parameters. See
[Differences from the ROS 1 version](#differences-from-the-ros-1-version)
below if you're coming from the original package.

The port was generated by Claude (Sonnet 5, High)

## Building

```bash
cd ~/ros2_ws
colcon build --packages-select opencv_apps
source install/setup.bash
```

## Running a node

Every node can be run standalone:

```bash
ros2 run opencv_apps edge_detection --ros-args -r image:=/camera/image_raw
```

or via its launch file, which declares the same parameters as launch
arguments:

```bash
ros2 launch opencv_apps edge_detection.launch.py image:=/camera/image_raw debug_view:=false
```

Each node subscribes to `image` (remap it to your camera's image topic) and
publishes its result(s) under its own private namespace, e.g.
`/edge_detection/image`, so that the input and output topics never collide
under a single remap. Nodes are lazy: they only subscribe to `image`
once something subscribes to one of their own outputs (or when
`always_subscribe:=true`, or implicitly whenever `debug_view:=true`).

Parameters replace the old `dynamic_reconfigure` GUI — list, inspect, and
change them at runtime with the standard ROS 2 parameter tools:

```bash
ros2 param list /edge_detection
ros2 param describe /edge_detection canny_threshold1
ros2 param set /edge_detection edge_type 2
```

Nodes can also be loaded into a component container instead of run standalone,
since they're all registered as `rclcpp_components`:

```bash
ros2 run rclcpp_components component_container
ros2 component load /ComponentManager opencv_apps opencv_apps::EdgeDetectionNode
```

`launch/example_composition_rgb_contour_moments.launch.py` shows this done
declaratively for a small pipeline: `rgb_color_filter` and `contour_moments`
loaded into one `ComposableNodeContainer`, with `contour_moments`'s `image`
input remapped to `rgb_color_filter`'s `~/image` output, both with
`use_intra_process_comms` enabled so the image passes between them without a
serialize/publish/subscribe round trip:

```bash
ros2 launch opencv_apps example_composition_rgb_contour_moments.launch.py image:=/camera/image_raw
ros2 component list          # shows both nodes loaded into one container
ros2 topic echo /contour_moments/moments
```

## Available nodes

| Category | Nodes |
|---|---|
| Filtering | `smoothing`, `morphology`, `pyramids`, `threshold`, `equalize_histogram`, `discrete_fourier_transform` |
| Color filtering | `rgb_color_filter`, `hls_color_filter`, `hsv_color_filter`, `lab_color_filter` |
| Edges / features / shapes | `edge_detection`, `corner_harris`, `goodfeature_track`, `find_contours`, `convex_hull`, `general_contours`, `contour_moments`, `hough_lines`, `hough_circles` |
| Optical flow | `lk_flow`, `fback_flow`, `simple_flow`, `phase_corr` |
| Tracking / segmentation | `camshift`, `segment_objects`, `watershed_segmentation` |
| Detection / recognition | `face_detection`, `face_recognition`, `people_detect` |
| Combining images | `adding_images` |
| Examples | `simple_example`, `simple_compressed_example` |

Run `ros2 param list <node>` after starting any of them to see its full set of
tunable parameters (each mirrors that node's old `cfg/*.cfg` 1:1), or read the
corresponding `launch/<node>.launch.py` file for the same information with
descriptions.

### face_recognition

`face_recognition` depends on `face_detection`'s output and exposes a
`~/train` service for registering new faces. The bundled launch file wires
both together, plus an interactive CLI trainer and an optional debug image
viewer:

```bash
ros2 launch opencv_apps face_recognition.launch.py
```

Say `launch_trainer:=false` or `debug_view:=false` to skip the trainer prompt
or the viewer window, respectively.

## Testing

```bash
colcon test --packages-select opencv_apps --ctest-args -R test_launch
colcon test-result --verbose
```

`test/test_launch_*.py` are `launch_testing`-based smoke tests that start a
node, feed it a synthetic image, and assert it publishes a result. They cover
3 representative nodes as a template rather than the full package.

The ROS 1 package's `test/*.test` rostest suite (33 files) was removed rather
than ported: it depended on ROS 1 bag files and the `hztest` tool, neither of
which exists in ROS 2, so keeping the old files around would have just
invited confusion about whether they still ran.

## Differences from the ROS 1 version

- **Parameters** replace `dynamic_reconfigure`: every cfg field is now a
  declared ROS 2 parameter, settable via `ros2 param set` or a launch
  argument, with the same name, default, and (where applicable) range.
- **Output topics are node-private** (`~/image`, `~/contours`, ...) rather
  than sharing the plain `image` name the input uses, so a single
  `-r image:=X` remap can't send both input and output to the same topic.
- **Lazy subscribe is polling-based** (checks every ~0.5s) rather than
  event-driven, since ROS 2's `image_transport` doesn't yet support
  subscriber connect/disconnect callbacks.
- **`camshift`'s learned histogram no longer persists across restarts.** In
  ROS 1 it was written back to the parameter server; in ROS 2 pass a known
  histogram via the `histogram` parameter instead.
- Two ROS 1 launch-file typos were fixed in the process: `hough_lines`'s
  `maxLineGrap` argument and `lk_flow`'s `blcok_size` argument now actually
  reach their nodes' real parameters (`maxLineGap` and `block_size`).
